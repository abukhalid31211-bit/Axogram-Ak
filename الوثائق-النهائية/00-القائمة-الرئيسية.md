# S00 — النظام العام + القائمة الرئيسية (Global UX System & Main Menu)

> هذه الوثيقة هي **المرجع الإلزامي الوحيد** لكل الأقسام (S01→S10). أي شاشة أو تدفق أو حالة لا تُعرَّف هنا تعرَّف في ملف قسمها مع إشارة للمرجع هنا.
> **نطاق النظام: القروبات فقط** (Basic Groups + Supergroups). لا قنوات ولا Broadcast Channels في أي شاشة أو منطق أو حالة.
> ملاحظة تقنية للمبرمج: في طبقة MTProto السوبر-قروب يُعامَل داخلياً كـ"channel"؛ أخطاء API لذلك تظهر بصيغة `CHANNEL_*` (`CHANNEL_PRIVATE`, `CHANNELS_TOO_MUCH`, `InviteToChannelRequest`…) لكنها في منتجنا تعني **قروباً** ولا علاقة لها بالقنوات النشرية. طبقة الترجمة G-ERR (§4) تتكفل بإخفاء هذا الالتباس عن المستخدم.

## 1. نظام الترقيم والمراجع

| العنصر | الصيغة | مثال |
|---|---|---|
| قسم | `S##` | `S03` = إضافة الأعضاء |
| تدفق داخل قسم | `S##-F#` | `S03-F2` = إضافة من ملف CSV |
| خطوة/شاشة داخل تدفق | `S##-F#-#` | `S03-F2-4` = خطوة التحقق من الهدف |
| مكوّن مشترك | `G-XXXX` | `G-ENSURE-JOIN` |
| حالة مرجعية | `الحالة «…»` | «تبريد 🧊» |
| انتقال | `──► [وجهة]` | `──► [S01-F5]` بطاقة الحساب |
| انتقال مع حمولة | `──► [وجهة](payload)` | `──► [S03-F2](file_id=F17)` |
| رجوع سياقي | `◄── RETURN` | يرجع لآخر شاشة في مكدس التنقل مع نتيجة |

**قاعدة الاستدعاء البيني:** أي قسم ينادي مكوّناً مشتركاً يمرّر له `RETURN_TARGET`؛ عند الإتمام يرجع المكوّن نتيجة موحدة: `{ ok, items, canceled, error }`.

## 3. الحالات المرجعية الموحدة (Canonical FSMs)

> هذه الآلات مرجعية؛ الأقسام تضيف حالاتها الخاصة لكن **لا تعيد تعريف هذه**.

### 3.1 آلة حالة أي عملية (JOB FSM) — تجميع/إضافة/حملة/تسخين/فحص/تصدير/تنظيف

```
مسودة📝 ──► مجدولة⏰ ──► في الطابور⌛ ──► جارية🟢 ──► مكتملة✅
                              │             ├─► متوقفة مؤقتاً⏸️ ──► جارية/ملغاة/جزئية☑️
                              │             ├─► راحة تلقائية😴 ──► جارية
                              │             ├─► تبريد🧊 (FloodWait) ──► جارية/مبدّلة
                              │             ├─► منقطعة تقنياً🔌 ──► إعادة n/3 ──► جارية | فاشلة❌
                              │             └─► فاشلة❌ / ملغاة🛑 / جزئية☑️(قابلة للاستئناف)
```
`جزئية☑️` تخزّن نقطة استئناف كاملة (§6.2). واجهة تنفيذها جميعاً = `G-OPS` (§5).

### 3.2 آلة حالة عنصر الهدف (TARGET FSM) — مستخدم/قروب داخل عملية

`قيد الانتظار` → `جارٍ` → أحد:
- `ok ✅` (مع مرجع النتيجة: message_id/عدد…)
- `skipped ⚠️ + reason_code`
- `failed ❌ + reason_code`
- `deferred ⏳ until=T` (Slowmode/راحة حساب — يُجدول تلقائياً)
- `retrying 🔁 attempt n/max`
- `interrupted 🔌` (مات الحساب/البروكسي منتصف التنفيذ ⇒ يعود للطابور، **لا يُحسب فشلاً**)
- `blacklisted 🚫`
- `ok-then-deleted ✅🗑` (حذف بعد الإرسال مع سجل)

### 3.3 آلة حالة الحساب (ACCOUNT FSM) — التفاصيل التشغيلية في S01

```
جديد غير مُتحقق ──► نشط🟢 (Free | Premium✦) ──► قيد التسخين🔥 ──► نشط
     │                    ├─► مقيد مؤقت⚠️(until) ──► نشط (تلقائي عند T)
     │                    ├─► مقيد دائم⛔ (إرسال DM | كتابة عامة | إنشاء قروبات)
     │                    ├─► مجمّد❄️ (FROZEN_* — قراءة فقط + مهلة استئناف)
     │                    ├─► محظور رقم⛔ / محذوف💀
     │                    ├─► جلسة ميتة🔑 (بحاجة إعادة دخول)
     │                    ├─► متعارض IP🔁 (AUTH_KEY_DUPLICATED)
     │                    └─► غير قابل للقياس🔌 (فشل تقني — فحص/بروكسي — ليس حظراً!)
```
**قاعدة ذهبية:** «غير قابل للقياس🔌» لا تتحول أبداً إلى «محظور» إلا بعد فحص ثانٍ بمسار اتصال سليم.

### 3.4 آلة حالة عضوية الحساب في قروب (MEMBERSHIP FSM)

```
غير منضم ──► جاري الانضمام ──► منضم ✅ / بانتظار موافقة📨 / فشل(name+سبب)
   منضم ──► مغادر طوعاً / مطرود👢 / منشئ👑 (لا يمكنه المغادرة — USER_CREATOR)
```
فشل الانضمام أسبابه: `رابط منتهي INVITE_HASH_EXPIRED` / `رابط غير صالح أو مُبطل INVITE_HASH_INVALID | INVITE_REVOKED_MISSING` / `قروب خاص ولست فيه CHANNEL_PRIVATE` / `محظور منه USER_BANNED_IN_CHANNEL` / `بلغ سقف العضويات USERS_TOO_MUCH | CHANNELS_TOO_MUCH` / `مجمّد FROZEN_PARTICIPANT_MISSING` / `FLOOD_WAIT_X`.

### 3.5 آلة حالة البروكسي (PROXY FSM)

`غير مختبر⚪` → `قيد الاختبار🔄` → `نشط🟢(latency)` | `بطيء⚠️(>حد ms)` | `ميت🔴+نوع الموت` | `محظور من تيليجرام🚫` | `منتهي الصلاحية⌛` | `موقوف يدوياً⏸️`
أنواع الموت: `timeout` / `رفض اتصال` / `فشل مصادقة` / `فشل DNS` / `خطأ بروتوكول (SOCKS4/5/HTTP/MTProto)` / `مفتاح MTProto غير صالح`.
حالة مشتقة على الحساب: `ميت-ومعيَّن⚠️` = الحساب مرتبط ببروكسي حالته ميت (يظهر في S01 و S05 ويستبعد من التدوير S04).

### 3.6 صلاحية الحساب داخل دورة التدوير (SLOT FSM)

`جاهز` | `حالي◀` | `التالي▶` | `راحة😴` | `تبريد🧊 until` | `بلغ الحد💤 (يصفر HH:MM)` | `خارج ساعات عمل🕐` | `يوم غير مسموح📅` | `موقوف يدوياً⏸️` | `مستبعد❌+سبب` | `في تسخين🔥`
وحالة نظام التدوير: `فراغ الدورة⏳ next_available_at=T` (لا حساب صالح الآن).

### 3.7 حالات ملفات الجلسات (SESSION FILE FSM)

`قيد الفحص` → `صالح✅` | `تالف❌ (بنية ناقصة)` | `مكرر🔁` | `منتهي (AUTH_KEY_UNREGISTERED | SESSION_REVOKED | SESSION_EXPIRED | USER_DEACTIVATED*)` | `محجوز بـ2FA مجهول` | `متعارض محتمل (نفس auth_key نشط في مكان آخر)`

## 4. G-ERR — محوّل أخطاء Telegram API ⟶ (حالة، إجراء، نص واجهة)

كل طبقة API تمر عبر `map_rpc_error(e) → {state, action, ui_text}`. الجدول المرجعي الكامل (الأقسام تضيف المتخصص فقط):

| خطأ API | الحالة الداخلية | الإجراء | نص الواجهة |
|---|---|---|---|
| `FLOOD_WAIT_X` (420) | تبريد🧊 T+X | إن X≤60: انتظار بنفس الحساب. وإلا: تبديل + تبريد الحساب | «تيليجرام طلب انتظار {X} — تم التبديل تلقائياً» |
| `FLOOD_PREMIUM_WAIT_X` (420) | تبريد🧊 (حساب غير Premium) | كسابق + وسم السجل | «تجاوز الحد المجاني — انتظار {X}» |
| `PEER_FLOOD` (400) | حساب مضغوط⚠️ | إخراجه من الدورة + راحة أيام + تنبيه عالٍ | «الحساب مضغوط نمطياً — أُخرج احترازياً» |
| `USER_RESTRICTED` (403/406) | مقيد⛔ | استبعاد + قفل الأدوات المتأثرة | «الحساب مقيّد من تيليجرام» |
| `USER_BANNED_IN_CHANNEL` (400) | مقيد-كتابة عامة⛔ | استبعاده من حملات القروبات فقط | «ممنوع من الكتابة في القروبات» |
| `FROZEN_METHOD_INVALID` (420) / `FROZEN_PARTICIPANT_MISSING` (400) | مجمّد❄️ | إيقاف كل أعماله + تنبيه حرج | «الحساب مجمّد (قراءة فقط) — راجع S08» |
| `PHONE_NUMBER_BANNED` / `USER_DEACTIVATED` / `USER_DEACTIVATED_BAN` | محظور/محذوف 💀 | أرشفة الجلسة + إزالة من كل الدورات | «الحساب محظور/محذوف نهائياً» |
| `AUTH_KEY_UNREGISTERED` `AUTH_KEY_INVALID` `SESSION_EXPIRED` `SESSION_REVOKED` (401) | جلسة ميتة🔑 | حالة «بحاجة إعادة دخول» | «انتهت الجلسة — أعد تسجيل الدخول» |
| `AUTH_KEY_DUPLICATED` (406) | متعارض IP🔁 | إيقاف أحد المثيلين | «الجلسة مستخدمة من مكانين — أُوقفت» |
| `SESSION_TOO_FRESH_X` `PASSWORD_TOO_FRESH_X` `FRESH_RESET_AUTHORISATION_FORBIDDEN` `FRESH_CHANGE_ADMINS_FORBIDDEN` | مؤجل إجبارياً⏳ | جدولة بعد X + عرض عدّاد | «حماية الحسابات الحديثة — تُنفذ بعد {X}» |
| `303 NETWORK/PHONE/USER/FILE_MIGRATE_X` | توجيه DC🔌 | إعادة اتصال بالـ DC `{new_dc}` شفافياً | (صامت، يظهر في السجل فقط) |
| `TIMEOUT` `RPC_CALL_FAIL` `RPC_MCGET_FAIL` `INTERDC_X_CALL_ERROR` `HISTORY_GET_FAILED` `SIGN_IN_FAILED` (500) | خطأ خادم🔌 | إعادة n/3 بتصاعد ثم failed | «خلل مؤقت في خوادم تيليجرام — إعادة…» |
| مهلة الشبكة/البروكسي (محلي) | غير قابل للقياس🔌 | تبديل بروكسي/إعادة | «تعذر الاتصال — يُحاول بمسار آخر» |
| `CHAT_ID_INVALID` `CHANNEL_INVALID` `PEER_ID_INVALID` `USER_ID_INVALID` `USERNAME_NOT_OCCUPIED` | هدف غير موجود | skipped على العنصر + تعليم الملف | «المعرّف غير موجود» |
| `AUTH_RESTART` (500) | إعادة سير الدخول | من الخطوة الأولى | «أُعيدت عملية الدخول من البداية» |
| `UPDATE_APP_TO_LOGIN` (406) | مكتبة/إصدار قديم | إيقاف + تنبيه مسؤول | «إصدار العميل قديم — حدّث المكتبة» |

## 5. G-OPS — شاشة تشغيل العمليات الموحدة

تُستخدم من: التجميع، الإضافة، حملات DM، حملات القروبات، التسخين، الفحص الشامل، فحص البروكسي، التنظيف، التصدير الضخم. تُفتح بحالة `JOB FSM` وتتحكم بها.

### 5.1 التخطيط (Desktop ≥1280)
- شريط علوي: اسم العملية + شارة حالتها (🟢 جارية…).
- منطقة تقدم: شريط نسبة + `[تم/الكل]` + سرعة لحظية + «الوقت المتبقي التقديري (تقديري لا يُعتمد)».
- بطاقة «النشط الآن»: الحساب الحالي (+بروكسيه) + العنصر الحالي + عداد اليوم للحساب `Y/حد`.
- سجل حي (Live Log): آخر 30 حدثاً، كل سطر «حالة رمز | عنصر | سبب» مع ألوان الحالات.
- جدول حالة الحسابات (مصغّر): ✅يعمل | 🧊يتبرد حتى T | 💤بلغ الحد | ⏸️موقوف | ❌خارج.
- أزرار ثابتة أسفل (Sticky bar — دائماً مرئية): `⏸️ إيقاف مؤقت` | `⏹️ إيقاف وحفظ` | `📊 تقرير لحظي` | `+ أبطئ 30%` | `- أسرع 30%` | `🔔 كتم/تفعيل`.

### 5.2 Responsive
- Tablet (768–1279): الجدول المصغّر يتحول لتبويب أفقي بطاقات.
- Mobile (<768): شريط التقدم + بطاقة النشط في الأعلى؛ السجل الحي أسفل بخاصية «توسيع»؛ الأزرار تنضغط إلى FAB + Bottom Sheet (ورقة سفلية).

### 5.3 حالات الشاشة نفسها
| الحالة | العرض |
|---|---|
| تهيئة | «⏳ تجهيز العملية…» (تحقق مسبق) |
| جارية | التخطيط أعلاه، تحديث لحظي عبر WebSocket؛ fallback استقصاء 5ث |
| متوقفة مؤقتاً | بانر «⏸️ متوقفة — التقدم محفوظ عند {i/N}» + أزرار: ▶️ استئناف الآن | ⏱️ استئناف بعد {حقل دقائق} | ✏️ تعديل الإعدادات ثم استئناف (──► آخر خطوات المُنشئ مع بقاء نقطة التقدم) | ⏹️ إنهاء كجزئية☑️ |
| راحة😴 | «راحة تلقائية — المتبقي HH:MM» + زران: «تخطي الراحة (غير موصى به ⚠️)» «⏸️ إيقاف مؤقت» |
| تبريد🧊 | «الحساب {p} في انتظار تيليجرام حتى {T} — {متبقي}»؛ إن بُرّدت كل الحسابات: «كل الحسابات في تبريد — سأستأنف عند {minT}» |
| منقطعة🔌 | «انقطع الاتصال — إعادة {n}/3 بعد {t}ث»؛ عند استنفادها ──► فاشلة❌ مع سبب |
| منبه أثناءها (FloodWait/حظر/طرد…) | بطاقة منبثقة: ما حدث + الإجراء الآلي المُتّخذ + أزرار: «OK متابعة» «P إيقاف» «X إيقاف وحفظ» — والمنبه لا يوقف العملية إن نصَّ الإجراء الافتراضي على المتابعة (S06-F6) |
| مكتملة✅ | شاشة النتيجة (§5.4) |
| فاشلة❌/ملغاة🛑 | شاشة سبب + خيارات: 🔁 إعادة | 📤 تصدير التقرير | 🏠 |

### 5.4 شاشة النتيجة (موحدة)
بطاقات: ✅ناجح (عدد+نسبة) | ⚠️متخطى + توزيع الأسباب | ❌فاشل + توزيع الأسباب | 🕐المدة | عدد FloodWaits | التبديلات | أداء كل حساب (جدول صغير).
أزرار: `📋 قائمة الفاشلة` (تحديد → إعادة للمحدد | سوداء | تصدير CSV) | `🔁 إعادة للفاشلة فقط` | `⏰ جدولة إعادة (غداً/أسبوع/تاريخ)` | `📤 تصدير التقرير` (PDF/TXT/CSV) | `🏠 القائمة الرئيسية` | `◄── RETURN` للقسم.

## 6. قواعد البيانات والاستمرارية

### 6.1 مخزن الحالات المركزي
جداول: `account_state(account_id, state, reason_code, until, updated_at)` | `proxy_state` | `job_state(job_id, fsm, progress[i,n], checkpoint, config_snapshot)` | `target_state(job_id, target, fsm, reason, attempts, ref)` | `group_membership(account_id, group_id, state, until)`.

### 6.2 نقطة الاستئناف (Checkpoint)
تحفظ كل «حدث حفظ» المضبوط بالإعداد: آخر فهرس هدف، عدّادات كل حساب اليومية، لقطة الإعدادات (لتمييز «استئناف بنفسها/معدّلة»)، خريطة العناصر الناجحة (Idempotency-key = job_id+target_id) لمنع الإرسال/الإضافة المكررة عند الاستئناف.

### 6.3 عناصر «نجح غير مؤكد»
إذا مات تسجيل بعد نجاح فعلي محتمل ⇒ العنصر `uncertain`، وعند الاستئناف يُسأل أو يُفحص (وجود رسالة/عضوية) بدل التنفيذ الأعمى.

## 7. نظام التنقل العام (G-NAV)

### 7.1 الهيكل
- **Desktop ≥1280:** Sidebar مطوّل (أقسام S01–S10 + شارات: ⚠️تنبيهات/🔒قفل) + Topbar (مسار Breadcrumb، حالة النظام، 🔔 مركز التنبيهات، قائمة المستخدم) + محتوى.
- **Tablet 768–1279:** Sidebar مطويّاً بأيقونات (يُفتح overlay).
- **Mobile <768:** Bottom Nav بخمس خانات (الرئيسية، الحسابات، العمليات، البروكسي/القروبات حسب السياق، المزيد●●●) + Drawer.

### 7.2 قواعد المكدس
- `🔙 رجوع` = Pop من المكدس (ليس «القائمة السابقة» دائماً).
- كل شاشة تحمل `crumb` ثابتاً: `الرئيسية / S03 / إضافة من ملف / التحقق`.
- فتح مكوّن مشترك بدفع إلى المكدس مع `RETURN_TARGET`.
- **حارس التعديلات:** أي شاشة فيها `dirty=true` ومحاولة خروج ⇒ مودال: «لديك تعديلات غير محفوظة — 💾 حفظ / تجاهل / متابعة التحرير».
- **حارس العملية الجارية:** الخروج من G-OPS أثناء «جارية» ⇒ «ستبقى تعمل بالخلفية — خروج للمراقبة اللاحقة من S07-F2»؛ لا يوجد إغلاق يقتل العملية إلا عبر ⏹️.

### 7.3 سجل الروابط العميقة (Deep Links Registry)
| الرابط | الوجهة | الحمولة | سلوك العودة |
|---|---|---|---|
| `S01-F2` | إضافة حساب | — | — |
| `S01-F5` | بطاقة حساب | `account_id` | ◄── للقائمة |

## 8. حالات الواجهة العالمية الست (G-SCREEN-STATES) — إلزامية لكل شاشة

| # | الحالة | التصميم | النص |
|---|---|---|---|
| 1 | تحميل أولي | Skeleton يحاكي التخطيط | «⏳ جاري التحميل…» |
| 2 | فارغ | أيقونة + عنوان + إرشاد + CTA | مثال: «لا حسابات بعد» + زر «➕ إضافة أول حساب» |
| 3 | خطأ تحميل | بانر داخل الشاشة | «❌ فشل الجلب: {سبب}» + زر «🔁 إعادة» |
| 4 | متقادم (Stale) | شريط رفيع أصفر أعلى القائمة | «البيانات منذ {t} — 🔄 تحديث» (مع auto-refresh ساكت) |
| 5 | معطّل بسبب | الزر معطّل + Tooltip/سطر سبب تحته | «معطّل: {السبب}» (مثال: API غير مضبوط ──► S06-F2) |
| 6 | نتائج جزئية/ترقيم | أسفل الجدول | «عرض {a}–{b} من {n}» + التالي/السابق (أو تحميل لانهائي على الموبايل مع فاصل «نهاية القائمة») |

**حالات الحقول:** فارغ / صالح ✅ / قيد التحقق ⏳(خادمي) / غير صالح ❌ + نص السبب تحت الحقل / معدّل غير محفوظ (نقطة برتقالية).
**G-TOAST:** نجاح (أخضر أسفل-يسار على Desktop، أعلى على Mobile) / خطأ (أحمر + زر تفاصيل) / معلومة. مدة 4–6ث، تتكدس ≤3.
**G-CONFIRM:** مودال تأكيد بمستويين: عادي (تأكيد/إلغاء) وخطير (أحمر + كتابة كلمة أو عدّاد 3ث) — للحذف الجماعي، مسح السجلات، الطوارئ.
**أزرار الإجراءات المهلِكة دائماً مودال خطير.**

## 9. نظام Responsive الكامل (G-RWD)

- **الجداول:** Desktop جدول كامل؛ Tablet يُخفي أعمدة ثانوية (قائمة «أعمدة»)؛ Mobile يتحول لبطاقات (سطر عنوان + حقول مفتاحية) مع سحب-يمين لإجراءات سريعة (⏸️/🗑) وسحب-يسار للتفاصيل.
- **أهداف اللمس ≥44×44px**، تباعد ≥8px.
- **عوامل الخط:** 14–16px، تباين WCAG AA؛ الوضع RTL افتراضي (والإنجليزية تنقلب LTR تلقائياً؛ الاتجاه من إعداد اللغة S06-F7).
- **لوحة المفاتيح:** `/` بحث، `Esc` رجوع/إغلاق، `Enter` تأكيد، `Space` تحديد صف، `?` قائمة الاختصارات؛ كل مودال يلتقط التركيز (focus-trap).
- **الوصولية:** aria-labels لكل زر أيقوني؛ شارة حالة لها رمز + نص (لا لون فقط).
- **الحمل الطويل (G-OPS):** لا تُحظر الواجهة؛ كل شيء خلفي مع مركز عمليات (S07-F2).
- **الطباعة/التصدير المعاين:** عرض PDF داخل مودال مع أزرار تحميل/إرسال.

## 10. شاشة دخول اللوحة وحدود الجلسة (G-AUTH)

1. **الدخول:** بريد+كلمة مرور → حالات: `تحقق جارٍ⏳` / `خطأ بيانات ❌` («بيانات غير صحيحة — بقي {n} محاولات») / `قفل مؤقت بعد تكرار` / **نجاح** ──► S00-F1. إن فعّل المستخدم «تقييد IP» وكان IP خارج القائمة: «الوصول مرفوض من هذا العنوان».
2. **انتهاء جلسة اللوحة (Session Timeout من S06-F11):** أي طلب 401 ⇒ قفل الشاشة بمودال «انتهت الجلسة — أدخل كلمة المرور لمتابعة» بدون فقدان حالة الشاشة.
3. **إشعار دخول جديد** يظهر في مركز التنبيهات + سجل S06-F11.

## 12. المكونات المشتركة (G-COMPONENTS) — تعريف وظيفي

### 12.1 G-ACCT-PICK — منتقي الحسابات
مدخلات: `mode: single|multi|pool|smart`، `filter` (نشط/يملك حداً متبقياً/عضو بقروبات الهدف=group_ids[])، `for: scrape|add|dm|campaign|warm|check`، `RETURN_TARGET`.
العرض: جدول (هاتف|اسم|صحة|الحالة|حد اليوم المتبقي|بروكسي|مجموعة) + بحث + فلاتر + تحديد الكل + «أرقام مخصصة (فواصل)».
حالات خاصة: `لا نتائج فارغ` / صفوف معطلة مع سبب (مقيد❌/تبريد🧊 حتى T/خارج دوامه) ولا يمكن تحديدها إلا بتجاوز يدوي مع تحذير.
وضع `smart`: بطاقة شرح «سيُختار: الأعلى صحة + الأقل استهلاكاً + الأقدم + الأعضاء بقروبات الهدف» + معاينة النتيجة قبل التأكيد.
RETURN: `{account_ids[], smart:bool}`.

### 12.2 G-PROXY-PICK — منتقي البروكسي
قائمة النشطة فقط افتراضياً (سرعة|نوع|موقع|حالة) + زر «اختبار قبل التعيين» (⏳→✅Xms/❌سبب) + خيار «بدون بروكسي» (تحذير إن كان الإعداد يتطلبه) + «اختيار تلقائي». RETURN: `{proxy_id|null}`.

### 12.3 G-FILE-PICK — منتقي ملفات الأعضاء
جدول (اسم|مصدر|عدد|تاريخ|حجم) + بحث + فرز + «📁 رفع ملف جديد» (سحب-وإفلات Desktop/اختيار Mobile، ≤50MB CSV) + معاينة أول 5 صفوف. RETURN: `{file_id}`.

### 12.4 G-GROUP-LINK — حقل رابط قروب + تحليل
يقبل: `t.me/name` أو `@name` أو `t.me/+hash` أو `t.me/joinchat/hash`.
خطوات التحقق التسلسلية (Spinner لكلي):
1. صيغة — خطأ محلي: «صيغة الرابط غير مفهومة».
2. تحليل الكيان (`contacts.resolveUsername` أو `messages.checkChatInvite`) —
   - `USERNAME_NOT_OCCUPIED/INVITE_HASH_INVALID` ⇒ «القروب غير موجود أو الرابط خاطئ»
   - `INVITE_HASH_EXPIRED/INVITE_REVOKED_MISSING` ⇒ «رابط الدعوة منتهٍ أو أُبطل»
   - `CHANNEL_PRIVATE` ⇒ «قروب خاص — تحتاج رابط دعوة ساري أو حساب عضو»
   - `FLOOD_WAIT` على resolve ⇒ تبديل حساب التحليل (حد التحليل ≈200/يوم — الحالة «مستهلك حد البحث»)
3. بطاقة القروب: الاسم | النوع (عادي/سوبر | عام/خاص) | عدد الأعضاء | الوصف | **شارة العضوية لكل حساب مختار** (منضم ✅/غير منضم ⬜/محظور ⛔).
إن كان الكيان الناتج «قناة نشرية» ⇒ رفض واضح: «هذا ليس قروباً — القنوات غير مدعومة في هذا النظام» + إبطال التدفق (قاعدة نطاق صلبة).
RETURN: `{group, membership_by_account}`.

### 12.5 G-ENSURE-JOIN — ضمان العضوية (القاعدة التي طُلبت صراحة)
> يسري على كل تدفق يحتاج عضوية (تجميع/إضافة/حملة قروبات/إرسال قروب/قراءة سجل).

```
لكل حساب مرشح h على القروب g:
  هل h منضم لـ g؟ (GetFullChannel/GetFullChat أو ذاكرة membership مع تحقق عند الشك)
  ├─ نعم ✅ ──► متابعة
  ├─ لا ⬜ ──► حالة «غير منضم» + زر [انضمام الآن] (أو تلقائي إن فُعّل إعداد التدفق)
  │     ├── جاري الانضمام ⏳ …
  │     ├── ✅ منضم ──► متابعة  (يُسجَّل LAST_JOINED_AT لرصد «الانضمام حديثاً»)
  │     ├── 📨 INVITE_REQUEST_SENT ──► «بانتظار موافقة المشرف» (h يُستبعد من g مؤقتاً — أو يبقى وضع «معلّق بالموافقة» إن كانت العملية طويلة)
  │     └── ❌ فشل + السبب (§3.4) ──► بطاقة: «تعذر انضمام {h}: {سبب}» + [استبدال بحساب آخر ⟶ G-ACCT-PICK] [تخطي هذا القروب لهذا الحساب] [إلغاء]
  └─ محظور منه ⛔ (USER_BANNED_IN_CHANNEL عند المحاولة السابقة) ──► استبعاد h من g + تسجيل
```
عرض مجمّع لعدة حسابات×قروبات: **مصفوفة تغطية** (صفوف=حسابات، أعمدة=قروبات، خلية ✅/⬜/⛔/📨) مع زر «إصلاح الكل: انضم لما هو ممكن» + ملخص «جاهزية الإرسال: x من y قروب مغطى».

### 12.6 G-ACCOUNTS-STRATEGY — اختيار الحسابات وقواعد التوزيع (مشترك S03/S09/S10)
1. اختيار: G-ACCT-PICK بأوضاعه الأربعة.
2. التوزيع: تسلسلي🔁 | حصص📦 | عشوائي🎲 | ذكي🧠⭐ (عضوية+حدود+صحة+عمر).
3. الحدود: مفتاح/تبديل، حد يومي/حساب (مع preset محافظ⭐/متوسط/عدواني/مخصص) أو «حد ذكي» (جديد<30ي: 10 | 1–6ش: 20 | >6ش: 35 — ومع Premium +هامش).
4. التأخير: بين العمليات و بين الحسابات (presets مع ⭐ وتحذير ⚠️/⛔) أو «ذكي» (يتكيف مع FloodWaits).
تحقق مباشر أثناء الاختيار: تحذيرات (لا حساب عضواً بهدف بعد G-ENSURE-JOIN / حد أقل من العدد / حسابات قيد التبريد) + إجمالي طاقة اليوم «تقدير: ~X عملية/يوم».

### 12.7 G-PROTECTION — إعدادات الحماية (مشتركة)
سلوك عند: FloodWait (انتظار+متابعة⭐/تبديل/إيقاف) | حظر حساب (إزالة⭐/إيقاف) | خصوصية مغلقة (تخطي⭐/تخطي+سوداء) | أخطاء القروب الخاصة في S10 | حد إيقاف الفشل (افتراضي 30%) | حفظ التقدم كل N | حذف بعد الإرسال (لا/ساعة/6س/24س/مخصص) | إشعارات الحدث الحرج.
RETURN: `protection_config` محفوظة كقابلة للتسمية (Preset).

### 12.8 G-SCHEDULE — توقيت وحدوث
فوراً▶️ | وقت محدد⏰ | متكرر🔁 (يومي/كل X أيام/أسبوعي/مخصص) مع بداية/نهاية (♾️/تاريخ/عدد تكرارات) | قواعد الراحة (راحة بعد N، حظر الليل، حظر يوم، محاكاة بشرية).
حالات: `SCHEDULE_DATE_TOO_LATE (>~سنة)` ⇒ «التاريخ بعيد جداً» | تاريخ ماضٍ ⇒ «سيُنفذ فوراً» | صيغة خاطئة.

### 12.9 G-SPIN — رسائل متنوعة (S09/S10)
عدد النسخ (3/⭐5/10/مخصص) → تحرير كل نسخة (حالة لكل نسخة: فارغ/غير مكتمل/جاهز) → «G توليد من النسخة الأولى» (⏳/✅/فشل) → طريقة التوزيع (عشوائي/تسلسلي/متساوٍ) → جدول النسخ بمعاينة/تعديل/حذف → تأكيد.

### 12.10 G-TEMPLATE-PICK — منتقي القوالب
بحث + فلتر تصنيف + معاينة (المحتوى كما سيصل مع متغيرات معبأة ببيانات تجريبية) + [استخدام] [تعديل ثم استخدام] + إحصاء (استخدامات|نجاح%).

### 12.11 G-BLACKLIST — القوائم السوداء (mode: users|groups)
عرض (جدول+بحث+فلتر سبب) / إضافة يدوي (مع تحقق هدف عبر G-GROUP-LINK للقروبات أو resolve للمستخدمين: `USERNAME_NOT_OCCUPIED` ⇒ «غير موجود») / استيراد TXT-CSV (تحليل ⏳ → نتيجة: صالح X | مكرر Y | مشوه Z) / حذف واحد/محدد / مسح الكل (مودال خطير) / تصدير.
مصادر الأسباب الموحدة (users): «خصوصية مغلقة | حظر الحساب-المرسل | طلب إزالة | فشل متكرر | يدوي».
سبب (groups): «طرد👢 | Slowmode دائم | Admin only | ممنوع المحتوى | غير متاح | يدوي».

### 12.12 G-EXPORT — واجهة التصدير الموحدة
نطاق (فترة/محدد) → صيغة PDF/CSV/TXT/XLSX → ⏳ توليد → ✅ «جاهز» مع [تحميل] + [إرسال كمرفق] — وتحقق المرفق: جلسة مستخدم (≤2GB مجاني / ≤4GB Premium) وإذا عبر بوت إشعارات (≤50MB) — فوقه: «الملف أكبر من حد الإرسال — متاح للتحميل فقط».

### 12.13 G-WIZARD — إطار المعالجات (S09/S10)
شريط خطوات علوي (رقم+اسم+حالة: تمت✅|حالية🔵|قادمة⚪|بها خلل🔴) + تنقل حر للخطوات المكتملة + حفظ مسودة تلقائي عند كل خطوة + مؤشر «💾 محفوظ قبل {t}» + حارس الخروج + في الخطوة الأخيرة بطاقة ملخص شاملة + تقديرات + تحذيرات + أزرار الإطلاق (§5.4/§12.8).
