# S01 — مدير الحسابات (Account Manager)

> المراجع الإلزامية: الحالات (S00 §3)، تحويل الأخطاء (S00 §4)، حالات الواجهة (S00 §8)، التنقل (S00 §7)، المكونات المشتركة (S00 §12).
> نطاق القروبات فقط: كل أنشطة التسخين تستهدف **قروبات عامة** (لا قنوات إطلاقاً).

## 0. بطاقة القسم

- **الغرض:** دورة حياة حسابات تيليجرام كاملة: إضافة/استيراد → تحقق وتصنيف → تسخين → تشغيل → أمان → أرشفة.
- **يعتمد على:** S06-F2 (API ID/Hash إلزامي)، S05 (بروكسي اختياري)، S08 (يكتمل تنفيذ الأمان هناك).
- **يغذي:** كل الأقسام (S02/S03/S04/S09/S10) عبر G-ACCT-PICK وحالات ACCOUNT FSM.
- **حالة ATM صلاحية القسم:** إن لم تُضبط API في S06-F2 ⇒ كل الأزرار الإجرائية بالحالة 5 «معطّل: API غير مضبوط ──► S06-F2».

## 1. S01-F1 — شاشة القسم الرئيسية (Dashboard)

### التخطيط
- **لوحة إحصائية (بطاقات):** 🟢نشط X | ⛔محظور Y | ⚠️مقيد Z | ❄️مجمّد | 🔑جلسة ميتة | 📊إجمالي | «صحة الأسطول: XX%» | زر تحديث 🔄.
- **قائمة إجراءات القسم** (S01-F2 … S01-F15).
- Desktop: شبكة بطاقات + قائمة جانبية فرعية. Mobile: البطاقات أفقية قابلة للتمرير + القوائم عمودية.
- حالات الشاشة الست (S00 §8) كاملة؛ «فارغ» = وضع البدء الموجّه في S00-F1.
- اللوحة تسحب من `account_state` لحظياً؛ عند أي اختلاف حديث: شارة «تغيّرت حالة {X} حساب منذ آخر زيارة — [عرض]» وأزرار فلترة سريعة.

## 2. S01-F2 — إضافة حساب جديد (مسار OTP الكامل)

**الشروط المسبقة:** API مضبوط؛ لا عملية دخول أخرى جارية لنفس الرقم.

### خطوة 1 — إدخال الرقم
- حقل «📱 رقم الهاتف بالصيغة الدولية (+9665…)» مع ماسك إدخال (تحقق محلي: صيغة دولية صحيحة، طول).
- زر «إرسال الرمز».
- **أحداث API المحتملة ⟶ الواجهة:**
| الحدث | الواجهة |
|---|---|
| ⏳ `sendCodeRequest` جارٍ | تعطيل الزر + «جاري الإرسال…» |
| `PHONE_NUMBER_INVALID` | «الرقم غير صالح — تحقق من الصيغة الدولية» |
| `PHONE_NUMBER_UNOCCUPIED` | بطاقة تنبيه: «هذا الرقم غير مسجّل في تيليجرام» (لا ندعم إنشاء الحسابات من الأداة) |
| `PHONE_NUMBER_BANNED` | «الرقم محظور من تيليجرام نهائياً» — يُسجَّل ويُرفض |
| `PHONE_NUMBER_FLOOD` (400) | «طُلب الرمز مرات كثيرة — جرّب مساءً» (قفل مؤقت للرقم 24س داخلياً) |
| `FLOOD_WAIT_X` | عدّاد تنازلي ثم إتاحة إعادة الإرسال |
| `SEND_CODE_UNAVAILABLE` (406) | «استُنفدت طرق الإرسال — أعد المحاولة لاحقاً» |
| `PHONE_NUMBER_APP_SIGNUP_FORBIDDEN` | «هذا الرقم لا يقبل التسجيل عبر API» |
| `AUTH_RESTART` / `UPDATE_APP_TO_LOGIN` | تنبيه مسؤول + إعادة من البداية |
| خطأ شبكة | الحالة 3 + إعادة |
- عند النجاح: تخزين `phone_code_hash` + عرض **نوع وصول الرمز**: «أُرسل الرمز داخل تيليجرام / عبر SMS / مكالمة» (تلقائياً من نوع الوصول) ──► خطوة 2.

### خطوة 2 — إدخال رمز OTP
- حقل «🔢 الرمز (من 5 خانات)» — ماسك أرقام؛ رسالة إرشاد: «أدخل الرمز الذي وصلك داخل تيليجرام لحسابك».
- زر «تأكيد» + «إعادة إرسال» (تُتاح بعد مهلة إعادة الإرسال؛ حالاتها: جاهزة/تبريد/استُهلكت `SEND_CODE_UNAVAILABLE`) + «تغيير الرقم» (◄── خطوة 1 مع بقاء القيمة).
- **أحداث:**
| الحدث | الواجهة |
|---|---|
| `PHONE_CODE_EMPTY` | «أدخل الرمز أولاً» |
| `PHONE_CODE_INVALID` | «رمز غير صحيح — المحاولة {n}/5» (بعد 5: إعادة من الخطوة 1) |
| `PHONE_CODE_EXPIRED` | «انتهت صلاحية الرمز — أُرسل جديد تلقائياً» ──► إعادة إرسال آلية؛ ملاحظة: إرسال جديد يُبطل القديم |
| `PHONE_CODE_HASH_EMPTY/PHONE_HASH_EXPIRED` | إعادة الخطوة 1 تلقائياً مع إشعار |
| خطأ شبكة/500 | إعادة مع الحفاظ على الخطوة |

### خطوة 3 — فحص 2FA
- النظام يستدعي `account.getPassword`:
| الحالة | المسار |
|---|---|
| لا 2FA | «🔓 الحساب بلا تحقق بخطوتين» ──► خطوة 4 فوراً |
| `SESSION_PASSWORD_NEEDED` (401) | حقل «🔐 كلمة مرور التحقق بخطوتين» + «نسيتها؟» ──► S08-F8 (وضع استرداد) |
| `PASSWORD_HASH_INVALID` | «كلمة مرور خاطئة — المحاولة {n}» + تحذير عند 3 |
| `PHONE_PASSWORD_FLOOD` (406) | «محاولات كثيرة — تيليجرام أوقف الدخول مؤقتاً» إيقاف التدفق |
| `PASSWORD_EMPTY` | «أدخل كلمة المرور» |

### خطوة 4 — نجاح الدخول + بطاقة الحساب
- ✅ «تم تسجيل الدخول» + بطاقة: الاسم | @username (قد يكون بدون — حالة خاصة «بدون اسم مستخدم») | الهاتف | الصورة | ✦Premium؟ | عمر الحساب «تقديري من المعرف» (وسم «تقديري — غير رسمي من API») | مركز البيانات DC}.
- التصنيف (إجباري): 🔴رئيسي | 🟡احتياطي | 🟢تجميع | 🔵إضافة | ⚪متعدد — اختيار واحد؛ الافتراضي ⚪ إن ضغط «تخطي».

### خطوة 5 — مجموعة وبروكسي
- «إضافة لمجموعة حسابات»: قائمة مجموعات──► S01-F7 أو «➕ إنشاء مجموعة» (حقل اسم + حفظ) — اختياري.
- «🌐 تعيين بروكسي الآن» ──► G-PROXY-PICK (RETURN) | «⏭ تخطي» (إن كان إعداد S05 إلزامياً: تحذير «سيُحظر على الحساب أي اتصال مباشر»).

### خطوة 6 — قرار التسخين
| الزر | الوجهة |
|---|---|
| «🔥 بدء التسخين فوراً» | ──► S01-F8 مع `account_id` محدداً مسبقاً |
| «⏭ تسخين لاحقاً» | إتمام ──► بطاقة نجاح نهائية |
| «✅ إضافة حساب آخر» | ◄── خطوة 1 (إعادة التدفق) |
| «🏠 مدير الحسابات» | ◄── S01-F1 |
| «❌ إلغاء» | في أي خطوة قبل 4: G-CONFIRM («سيُفقد تقدم الدخول»)؛ بعد 4: «إزالة الحساب المضاف؟» (نعم = حذف آمن للجلسة المنشأة) |

**حالة حساسة:** إن مات الاتصال بين خطوتي 2 و4 (الجلسة أُنشئت لكن البطاقة لم تُجلب): عند العودة يظهر «وُجدت جلسة منتهية جزئياً لهذا الرقم — استكمال الجلب من حيث توقفت» (idempotent).

## 3. S01-F3 — استيراد الجلسات

اختيار الطريقة (5 أزرار). كلها تشتغل «فحص ثم استيراد» بنفس نموذج النتائج:

### F3.1 📁 من مجلد / F3.2 📄 ملف واحد / F3.3 📋 ملف نصي (أرقام+جلسات) / F3.4 🔑 String Sessions / F3.5 📦 ZIP
خطوات: إدخال المسار/اللصق (لـString حقل متعدد ينتهي بـ«Done»؛ ZIP يُطلب كلمة مروره إن وُجدت) ──► «🔍 جاري الفحص… [i/N] %» ──► جدول النتائج لكل ملف وفق SESSION FILE FSM (S00 §3.7):
- ✅ صالح | ❌ تالف (بنية/محتوى ناقص) | 🔁 مكرر (نفس الحساب موجود) | ⌛ منتهي (الأسباب: `AUTH_KEY_UNREGISTERED/SESSION_REVOKED/SESSION_EXPIRED/USER_DEACTIVATED*`) | 🔐 محجوز بـ2FA مجهول (لا يمكن التحقق النهائي) | ⚠️ متعارض محتمل (نفس auth_key نشط حالياً هنا).
أحداث خاصة: «مسار غير موجود/قراءة ممنوعة» حالة 3 للحقل؛ «ZIP مشفر بكلمة خاطئة» إعادة إدخال؛ «تنسيق String غير مُعرّف» تجاوز بتحذير؛ «قرص ممتلئ أثناء الاستخراج» إيقاف مع السبب.
أزرار: «✅ استيراد الصالحة (X)» / «❌ إلغاء» / «🔙 رجوع».
بعد الاستيراد ──► شاشة ملخص: أُضيف X (يطلب منه التصنيف الجماعي إن أراد) + [🔥 تسخين المستوردة ──► S01-F8] [🏠].

## 4. S01-F4 — عرض الحسابات (الجدول + الإجراءات الجماعية)

- جدول: # | هاتف | اسم | تصنيف | صحة% | حالة | بروكسي | مجموعة | آخر استخدام. (Responsive: S00 §9).
- أدوات: بحث فوري (اسم/@/هاتف) | فلتر الحالة (كل حالات ACCOUNT FSM!) | فلتر التصنيف | فلتر المجموعة | فلتر الصحة (4 نطاقات) | ترتيب (صحة/آخر استخدام/عمر/استهلاك) | تحديد الكل/إلغاء الكل | «أرقام مخصصة».
- حالة «فارغ بعد الفلتر» ≠ فارغ المخزون (نص: «لا نتائج تطابق الفلاتر — مسح الفلاتر»).
- صف الحساب: شارة الحالة الملونة + نص؛ صف المعطّل (ميت جلسته) بخلفية رمادية والإجراءات عليه تُطلق بتحذير.

### إجراءات المحدد
| الزر | السلوك/الوجهة |
|---|---|
| 🗑 حذف المحدد | G-CONFIRM خطير («سيُحذف X حساباً وجلساتها من الأداة — لن يُحذف الحساب من تيليجرام») → ⏳ → ✅ «حُذف X» (أخطاء جزئية تُعرض) |
| 🔥 تسخين المحدد | ──► S01-F8 `account_ids[]` |
| ✅ تحقق من المحدد | ──► S01-F6 وضع «محددة» |
| 🌐 تعيين بروكسي | ──► G-PROXY-PICK (multi-assign) RETURN |
| 🏷️ تغيير تصنيف | قائمة التصنيفات → تطبيق فوري + Toast |
| 👥 نقل لمجموعة | قائمة مجموعات S01-F7 → تطبيق |
| نقرة الصف | ──► S01-F5 `account_id` |

## 5. S01-F5 — بطاقة تفاصيل الحساب

### المعلومات (بطاقات مرتبة)
1. أساسية: الاسم | @«بدون username» حالة | هاتف | ✦Premium | عمر «تقديري» | أُضيف للأداة بتاريخ | تصنيف/مجموعة/بروكسي (بالحالة المشتقة «‼️ميت-ومعيَّن» إن لزم) | صورة.
2. الصحة: شريط XX% + لون النطاق + زر «شرح الدرجات» ──► S01-F9.
3. إحصاءات: إجمالي (تجميع|إضافة|DM|قروبات) | اليوم | FloodWaits أسبوعياً | قروبات منضماً لها X | آخر استخدام.
4. جهاز الجلسة: Device/OS/AppVersion/DC (من الجلسة).
5. حالة الـ 2FA: مفعّل/غير؛ آخر فحص حماية.
- حالات الصفحة: تحميل/خطأ جلب تيليجرام (زر «🔄 جلب الآن من تيليجرام» — يقوم `getFullUser` مع حالاته: جلسة ميتة ⟶ تحويل الحساب فوراً لـ«جلسة ميتة 🔑» والبطاقة للحالة 3 مع سبب قابل للفعل).

### الأزرار (كلها ستظهر/تتعطل حسب حالة الحساب)
| الزر | السلوك/الوجهة | ملاحظات الحالة |
|---|---|---|
| ✏️ تعديل المعلومات | ──► S01-F11 فردي | للحالات 🟢 فقط |
| 🌐 تغيير البروكسي | ──► G-PROXY-PICK | يُسمح دوماً |
| 🔥 تسخينه | ──► S01-F8 | معطّل إن 🔥جاري/مقيد⛔ |
| ✅ التحقق الآن | ⏳ ──► نتيجة فورية بنفس قواعد S01-F6 (تحديث `account_state`) | — |
| 📋 سجل نشاطه | ──► S01-F12 `account_id` | — |
| 📤 تصدير الجلسة | [.session ملف] / [String] → G-EXPORT | تحذير «ملف حساس» في المودال |
| 🔄 تحديث المعلومات | جلب فوري أعلى البطاقة | — |
| ⚙️ إعدادات خاصة | ──► S01-F10 | — |
| ❄️/⛔ أزرار خاصة | «عرض تفاصيل التقييد من @SpamBot» ──► S08-F6؛ «محاولة استرداد الجلسة» إعادة دخول ──► S01-F2 بقفل الرقم | حسب الحالة |
| ❌ حذف الحساب | G-CONFIRM خطير ──► أرشفة الجلسة + إخراجه من S04 | — |

## 6. S01-F6 — التحقق من الصحة (Health Check)

### المداخل
- «فحص الكل» / «فحص محددة» (G-ACCT-PICK `for=check`).

### منطق الحكم على الحالة (بالترتيب)
1. اتصال بمساره (بروكسيه) — فشل: إعادة بمسار بديل؟ ثم «غير قابل للقياس 🔌» (لا يُحكم حظراً!).
2. `users.getUsers(self)` (get_me):
   - نجاح ⟶ 🟢 (مع التقاط ✦Premium).
   - `AUTH_KEY_UNREGISTERED/SESSION_REVOKED/SESSION_EXPIRED` ⟶ «جلسة ميتة🔑».
   - `USER_DEACTIVATED/USER_DEACTIVATED_BAN` ⟶ «محذوف/محظور💀».
   - `AUTH_KEY_DUPLICATED` ⟶ «متعارض IP🔁».
3. كشف التجميد: محاولة فعل خفيف (مثلاً `messages.getDialogs`) ⇒ `FROZEN_METHOD_INVALID/FROZEN_PARTICIPANT_MISSING` ⟶ «مجمّد❄️» (يُجلب تاريخ التجميد/الموعد النهائي إن أمكن من إشعار الحساب — وإلا مجهول).
4. كشف التقييد: محادثة @SpamBot (قراءة آخر رد آلي):
   - «FREE» ⟶ لا تقييد.
   - «LIMITED until …» ⟶ «مقيد مؤقت⚠️ حتى T» (تلقائياً: يعود نشطاً بعد T بفحص مجدول).
   - لا رفع/دائم ⟶ «مقيد دائم⛔».
   - تصنيف النوع (DM/كتابة عامة/إنشاء قروبات) يكتمل بخارطة أخطاء: `USER_BANNED_IN_CHANNEL` (كتابة عامة)، `USER_RESTRICTED` (إنشاء)، استبانة DM أثناء العمليات.
5. `PHONE_NUMBER_BANNED` (عند محاولة إعادة دخول) ⟶ «محظور⛔».

### شاشة التنفيذ = G-OPS (type=health_check)
تحديث حي للجدول: حساب|النتيجة|السبب|التالي. أزرار الإكمال: «🗑 إزالة المحظورة تلقائياً» (مودال خطير — يعطّل إن صفر) | «🔑 قائمة الجلسات الميتة» [إرشاد: إعادة دخول ──► S01-F2 أو أرشفة] | «📊 التقرير المفصل» (جدول + G-EXPORT) | «قفل المجمّدة ❄️ لمراجعة يدوية ──► S08-F6».

## 7. S01-F7 — مجموعات الحسابات (Account Pools)

- عرض: جدول (اسم|عدد|نشط|غرض|حالة صحة المجموعة) — حالة فارغ بالحالة 2.
- إنشاء: اسم (إجباري، فريد — خطأ «موجود») + وصف اختياري + غرض (تجميع/إضافة/رسائل/حملات قروبات/متعدد) ──► حفظ/إلغاء.
- تفاصيل مجموعة: معلومات + جدول حساباتها (نفس أدوات F4) +:
  - ➕ إضافة حسابات ──► G-ACCT-PICK («الغير مضافة» فلتر) RETURN.
  - ❌ إزالة حسابات (تحديد → تأكيد).
  - ✏️ تعديل الاسم/الغرض | 🗑 حذف (G-CONFIRM: «الحسابات تبقى — المجموعة فقط تُحذف») | 🔙.
- حالات ظهورها عبر الأقسام: تُستخدم كفلتر في G-ACCT-PICK (`mode=pool`).

## 8. S01-F8 — التسخين (Warm-up) — قروبات عامة فقط

### الإعداد
1. النطاق: «كل الجديدة» | G-ACCT-PICK (فلتر=جديد/ضعيف) | مجموعة كاملة.
2. أنشطة (☑️): «الانضمام لقروبات عامة نشطة عشوائية (من قائمة داخلية/بحث S02-F8)» | «ردود خفيفة داخل قروبات» | «مشاهدة/قراءة السجل» | «تغيير الصورة/البيو» | «إضافة جهات اتصال» | «تفاعلات إيموجي داخل القروب (إن فعّل القروب التفاعلات)» | «تغيير الاسم تدريجياً».
3. المدة: يوم 🟢 / 3 أيام 🟡 / ⭐7 أيام / 14 يوم 🔴 / مخصص (حقل).
4. الشدة: 🐢 5–10 | ⭐🚶 20–30 | 🏃 50–80 فعل/يوم (تحذير عند المكثف لحسابات <أسبوعين).

### التنفيذ = G-OPS (type=warmup) مع خصوصيات
- حالة لكل حساب داخل التسخين: `يوم X من Y` + «الفعل التالي بعد {t}» + مؤشر صحة يتحرك XX% → YY%.
- أخطاء النشاط: `CHANNELS_TOO_MUCH` («بلغ سقف عضويات القروبات 500/1000 — يوقف نشاط الانضمام له فقط») | `USER_BANNED_IN_CHANNEL` («ممنوع من الكتابة العامة — إيقاف التسخين للحساب + استبانة») | `FROZEN_*` ⟶ ❄️ إيقاف كامل له | `FLOOD_WAIT` تبريد🧊 | `CONTACT_NAME_EMPTY/CONTACT_ID_INVALID` (فشل إضافة جهة اتصال — يُتخطى العنصر) | أخطاء الصور `PHOTO_*` (S01-F11).
- الإنهاء: «اكتمل التسخين — الصحة الجديدة XX%» + تقرير + [🏠]. فشل بحظر أثناءه: الحساب ⟶ ⛔ + توقّف بقية الدفعة مع سؤال («متابعة البقية بحذر/إيقاف الكل»).

## 9. S01-F9 — درجة الصحة (Health Score)

- شرح النطاقات + جدول العوامل (عمر 20% | نشاط سابق 20% | FloodWaits 15% | قروبات 15% | صورة/بيو 10% | جهات اتصال 10% | سجل أخير 10%).
- ملاحظة شفافية (نص معلومة): «العمر تقديري من نطاق المعرف؛ آخر ظهور الآخرين/أرقام هواتفهم لا يمكن قياسها — تعتمد على خصوصية المالك».
- حالات الدرجة: «غير محسوبة» (حساب جديد — zöyف «احسب الآن» فردي) / «قيد الحساب ⏳» / المحسوبة بنطاقها.
- أزرار: «🔄 إعادة حساب للكل» (⏳ → ✅) | «⚠️ الضعيفة فقط (قائمة <70% + زر 🔥 تسخينها ──► S01-F8)».

## 10. S01-F10 — إعدادات فردية للحساب

اختيار حساب (G-ACCT-PICK single) ثم بطاقات:
- حدود يومية خاصة: تجميع [500] | إضافة [20] | DM [30] | قروبات [25] — حقل لكلٍّ + «إعادة للافتراضي» (S06-F3) + حالة الحقل (S00 §8).
- أولوية التدوير: 🔴عالية/🟡متوسطة⭐/🟢منخفضة (تستخدمها S04).
- قيود الاستخدام: ☑️ تجميع / إضافة / DM / قروبات / داخل التدوير.
- ساعات العمل: مفعّلة؟ من–إلى HH:MM (تحقق «من ≠ إلى» وصيغة) — تتكامل مع SLOT FSM «خارج ساعات عمل🕐».
- حفظ 💾 (حالة: «تم الحفظ»/فشل DB — حالة 3) — و«استخدامها الآن في الدورة» تلميح.

## 11. S01-F11 — مدير الملف الشخصي

### فردي
اختيار حساب ثم: صورة (رفع مسار/مجلد عشوائي/حذف) | اسم أول | اسم عائلة | @username | بيو (حقل متعدد ينتهي بـ«END») ──► «💾 حفظ» ⏳ جاري التطبيق على تيليجرام ⟶ نتيجة لكل بند:
| البند | أخطاء/API |
|---|---|
| @username | `USERNAME_INVALID` («صيغة خاطئة») / `USERNAME_OCCUPIED` («محجوز») / `USERNAME_NOT_MODIFIED` («نفس الحالي — لا حاجة») / `USERNAME_PURCHASE_AVAILABLE` («متاح بالشراء — غير مدعوم تلقائياً») |
| الأسماء | `FIRSTNAME_INVALID`/`LASTNAME_INVALID` (الحد 64) |
| البيو | `ABOUT_TOO_LONG` (70/140 Premium) |
| الصورة | `PHOTO_EXT_INVALID` / `PHOTO_INVALID_DIMENSIONS` / `PHOTO_CROP_SIZE_SMALL` / `PHOTO_SAVE_FILE_INVALID` (>10MB — «صغّر الصورة») |
بطاقة نتيجة: «✅ كل البنود» أو جدول بند×حالة.

### جماعي (Bulk)
تحديد حسابات + ما يُغير (صور من مجلد عشوائي / أسماء من ملف / بيو من ملف) + تأخير بين الحسابات ──► G-OPS(type=profile_bulk) بنفس أخطاء الفردي لكل عنصر (failed يذكر الحساب+البند).

## 12. S01-F12 — سجل نشاط الحسابات

- «سجل الكل»: بحث (حساب/نوع/تاريخ) + فلاتر (نوع: تجميع/إضافة/رسائل/أخطاء | تاريخ: اليوم/7ي/30ي/مخصص) + جدول (وقت|حساب|نوع|تفاصيل|نتيجة) — صف الحساب ينقر ──► S01-F5؛ تصدير (G-EXPORT).
- «سجل حساب»: اختيار حساب ──► نشاط + رسم 7 أيام + إجماليات. حالات: لا نشاط (فارغ)؛ سجلات قديمة مؤرشفة (بانر «البيانات قبل {T} مؤرشفة» ──► S07-F14).

## 13. S01-F13 — أمان الحسابات (روابط مباشرة إلى S08)

لتفادي الازدواجية، هنا تُعرض مختصرات ثم تُحوّل:
| العنصر | الوجهة |
|---|---|
| 🛡️ فحص أمان شامل (لحالة حساب واحد أو الكل) | ──► S08-F4 `account_id?` |
| 📱 أجهزة حساب محدد | ──► S08-F5 `account_id` |
| 🔐 تحديث 2FA | ──► S08-F8 `account_id` |
| 🔍 التحقق الفوري (حالة) | مثل S01-F5/التحقق (يبقى هنا للسرعة) |

## 14. S01-F14 — تصدير واستيراد (Backup & Restore الخاص بالقسم)

- تصدير جلسات: نطاق (الكل/محدد بـG-ACCT-PICK/مجموعة) + صيغة (.session / String نصي / ZIP مع ☑️ تشفير بكلمة مرور) + مسار ──► ⏳ ──► G-EXPORT (مع فحص حجم المرفق) — تحذير أمان دائم: «الملفات تفتح الحسابات — تعامل بسرية».
- تصدير بيانات (بدون جلسات): CSV/PDF بالحقول العامة.
- حالات فشل: «مسار غير قابل للكتابة»، «قرص ممتلئ»، «فشل قراءة جلسة X (يقفز ويُعلم)».

## 15. S01-F15 — إدارة غير النشطة

- «إزالة تلقائية للمحظورة»: فحص (⏳) → «وُجد X محظور/مقيد دائم» جدول → G-CONFIRM خطير → أرشفة.
- «تنظيف القديمة»: 30/60/90 يوم أو مخصص منذ آخر استخدام (يستثني: رئيسية🔴 ومجمّدة تحت استئناف) → نفس النمط.
- «حذف حساب محدد»: برقم أو هاتف (تحقق وجود) → تأكيد.
- الحالات: لا نتائج (فارغ «لا حسابات تطابق المعيار»)؛ أخطاء حذف ملف جلسة (يُسجّل ويستمر).
