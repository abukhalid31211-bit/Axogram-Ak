# S03 — إضافة الأعضاء (Add Members) — قروبات فقط

> المراجع: G-ERR، G-ENSURE-JOIN، G-ACCT-PICK، G-ACCOUNTS-STRATEGY، G-PROTECTION، G-OPS، G-BLACKLIST(users)، TARGET FSM.
> قاعدة نطاق: الهدف **قروب** (عادي أو سوبر). اختيار الطريقة التقنية للإضافة تلقائي: مجموعة عادية ⟶ `AddChatUserRequest` (حاجز ~200 عضو)؛ سوبر ⟶ `InviteToChannelRequest`.

## 0. بطاقة القسم
- **الغرض:** ضمّ أعضاء مستخرجين (S02) أو مدخولين يدوياً إلى قروب هدف، بحصص آمنة موزعة على الحسابات.
- **يعتمد على:** S01 (حسابات وعضوياتها)، S02 (ملفات)، S04 (يستدعيه للاختيار)، S05.
- **يغذي:** S07 (سجلات)، القوائم السوداء (G-BLACKLIST)، عدّادات S04 اليومية.
- **قيد عضوية إلزامي:** أي «حساب مُضيف» يجب أن يكون عضواً في القروب الهدف (G-ENSURE-JOIN قبل الإطلاق — مصفوفة التغطية).

## 1. S03-F1 — شاشة القسم (Dashboard)
بطاقات: 📤 مضاف اليوم/أسبوع/كل | ✅ناجح/⚠️تخطي/❌فاشل % | 🔄 آخر عملية | رابط سريع: «استئناف آخر جزئية ──► F6». حالات الواجهة الست.

## 2. S03-F2 — الإضافة من ملف CSV (المسار الرئيسي)

### الخطوة 1 — اختيار الملف: G-FILE-PICK
ثم تحليل آلية «🔍 تحليل…» ⟶ بطاقة: إجمالي X | بـ@username Y | بـID Z | ⚠️ «بدون username: W (سيُحاول بالـ ID عند الإمكان — والفاشل يتحول تخطياً)».
- حالات التحليل: «أعمدة غير مفهومة» (خريطة الأعمدة اليدوية) | «ملف تالف/فارغ» (حالة 3) | «صيغ مختلطة» (تسوية تلقائية).

### الخطوة 2 — القروب الهدف: G-GROUP-LINK ⟶ بطاقة الهدف
بالإضافة العامة تُعرض: هل عنوانه **عادي أم سوبر**؛ أعضاؤه الحاليون; **تقدير المقاعد قبل حاجز 200** (للعادي: «يتبقى {max(0,200-count)} مقعداً للإضافة المباشرة»).
- حالة خاصة (عادي): إن كان count ≥ ~195 أو سيتجاوز بعد الحملة ⟶ إنذار: «المجموعة العادية تقفَ عند 200 عضو — بعدها تفشل الإضافة المباشرة. الخيارات: [الترقية لسوبرقروب يدوياً من تيليجرام] [التحول لطريقة رابط الدعوة ⬇️]». (UI لا يوقف — يقدّر بيانياً.)

### الخطوة 3 — طريقة الإضافة
| الطريقة | التفصيل |
|---|---|
| 📲 إضافة مباشرة ⭐ | التقنية التلقائية حسب نوع الهدف (أعلاه) |
| 📨 دعوة عبر رسالة خاصة | **حملة DM بالدعوة** — تحوّل كلياً إلى S09-F1(file_id + نص دعوة جاهز) مع رجوع النتيجة؛ تُحسب عملياتها لحدود DM لا الإضافة |
| 🔗 إرسال رابط دعوة | إنشاء/جلب رابط دعوة للهدف: يتطلب عادة صلاحية «إنشاء روابط» — عند `CHAT_ADMIN_REQUIRED`: «حساب المنشئ ليس مشرفاً — أعطه الصلاحية أو اختر طريقة أخرى»؛ `CHANNEL_PRIVATE`: الهدف خاص لغير العضو | ثم تسليمها لمسار الإرسال المختار (مباشر عبر الإضافة مع الرابط رسالة، أو DM ──► S09) |

### الخطوة 4 — الحسابات: G-ACCOUNTS-STRATEGY(`for=add`)
- بعد الاختيار، **إلزامياً**: G-ENSURE-JOIN(حسابات مختارة × الهدف) ⟶ مصفوفة التغطية (بلد واحد هنا) → يُركّب:
  - ✅عضو | ⬜غير عضو ──► «انضمام الآن» (نتائج §12.5) | ⛔محظور منه (يُستبعد بنص) | 📨بانتظار موافقة (يُستبعد مؤقتاً).
  - شرط الإطلاق: ≥1 ✅. لافتة الحقيقة: «الحسابات الجاهزة للإضافة: X من Y».
- **كشف مُسبق للصلاحية في الهدف:** «هل الحساب مشرفاً؟» يُعرض كشارة معلوماتية؛ الإضافة المباشرة للسوبر لا تتطلبها غالباً لكن بعض القروبات تتطلب «موافقة الأعضاء الجدد» (Join-by-request — حالة: «الإضافات ستتحول طلبات📨» — تُحسب نصف-نجاح).

### الخطوة 5 — الفلاتر قبل الإضافة (☑️)
تخطي الموجودين مسبقاً (فحص حي بطيء — تحذير زمني، أو كشف عند الرفض `USER_ALREADY_PARTICIPANT`) | تخطي القائمة السوداء | بدون @username | المقيدين/المحذوفين | البوتات | «استبعاد من طُرد سابقاً من هذا الهدف» (سجل سابق `USER_KICKED`).

### الخطوة 6 — الحماية: G-PROTECTION
خاص بالإضافة: «بعد X فشل خصوصية متتابع على نفس القروب: إيقاف + مراجعة» (خطر طرد الحسابات)؛ تعليم الإعدادات الافتراضية S06/S03-F9.

### الخطوة 7 — الملخص والإطلاق
بطاقة (ملف|هدف|طريقة|حسابات جاهزة|توزيع|تأخير|حدود|فلاتر) + تقديرات «~X إضافة/يوم | ~Y يوم» + تحذيرات. ──► زر «بدء» ⟶ G-OPS(type=add).

### الإطلاق — حالات عنصر (Target FSM بالأسباب المتخصصة)
| الحالة + السبب | خطأ API |
|---|---|
| ✅ ok | أُضيف فعلاً |
| 📨 ok-invite-pending (نصف نجاح — عمود مستقل في التقرير) | `INVITE_REQUEST_SENT` (400) — أُرسل للمستخدم طلب/دعوة بانتظار موافقته |
| ⚠️ موجود مسبقاً | `USER_ALREADY_PARTICIPANT` |
| ⚠️ مدعو سابقاً | `USER_ALREADY_INVITED` |
| ⚠️ خصوصية مغلقة | `USER_PRIVACY_RESTRICTED` (403) |
| ⚠️ يقبل المتبادلين فقط | `USER_NOT_MUTUAL_CONTACT` |
| ⚠️ انضماماته ممتلئة | `USER_CHANNELS_TOO_MUCH` |
| ⚠️ طُرد سابقاً | `USER_KICKED` |
| ⚠️ بوت | `USER_IS_BOT` / `USER_BOT` |
| ⚠️ محذوف | `INPUT_USER_DEACTIVATED` / `USER_DELETED` (403) |
| ❌ معرّف غير موجود | `USER_ID_INVALID/USER_INVALID/PEER_ID_INVALID` + `USERNAME_NOT_OCCUPIED` عند التحليل المسبق و`PHONE_NOT_OCCUPIED` للإدخال بالهاتف |
| 💥 فشل بسبب الحساب (لا يُنسب للعنصر) | `PEER_FLOOD` («مضغوط نمطياً — استبعاد وراحة أيام») / `FLOOD_WAIT_X` (تبريد/تبديل) / `USER_RESTRICTED` / `USER_BANNED_IN_CHANNEL` / `FROZEN_*` ⟶ أيّها يُخرج الحساب (account_state) والعنصر يعود `interrupted 🔌` |
| ❌ يتطلب صلاحية | `CHAT_ADMIN_REQUIRED` |
| ⛔ حاجز 200 تحقق فعلياً أثناء التشغيل (عادي) | `USERS_TOO_MUCH` بصيغة «لا يمكن الإضافة بعد الآن» ⟶ تتوقف الإضافة المباشرة تلقائياً مع بطاقة قرار: «💡انتهى ~200 — [تحويل الباقي لطريقة رابط الدعوة] [إنهاء كجزئية☑️]» |

- تنبيهات G-OPS الحية لهذا النوع: FloodWait (تبديل+زيادة تأخير)، حظر/إقصاء حساب، «نسبة دعوات📨 مرتفعة» (>30%): معلومة (الهدف يفرض موافقات).

### الإنهاء — شاشة النتيجة (§5.4 S00) + خصوصياتها هنا
- عمود إضافي «📨 دعوات بالموافقة: X». زر «🔁 إعادة الفاشلين فقط» يفتح wizard جديداً بقائمة الفاشلين (بفلتر أسبابها مسبقاً: يستبعد المتوفاة/المحرومة). زر «🚫 إرسال المتعذّرين إلى القائمة السوداء» بفلترةشروطها.

## 3. S03-F3 — إضافة يدوية
- حقل متعدد «@username أو user_id أو هاتف» («Done») مع تحقق فوري لكل سطر بعد فاصلة:
  ⏳ ⟶ ✅صالح | ❌غير موجود (`USERNAME_NOT_OCCUPIED`/`PHONE_NOT_OCCUPIED`/معرّف غير قابل للحل) | ⚠️قائمة سوداء مسبقاً | 🔁مكرر في الإدخال.
- «إجمالي الصالح: X» ثم يُكمل من خطوة 2 بـF2 كاملاً (الهدف → …).

## 4. S03-F4 — إضافة ذكية (Smart Add: مصدر ⟶ هدف)
1. رابط المصدر (G-GROUP-LINK) + G-ENSURE-JOIN ⟶ اختيار نوع الالتقاط (نشطون/[يُعيد استخدام منطق S02] بسقف سريع).
2. رابط الهدف (نمط F2) + مصفوفة الحسابات (خطوة 4 بـF2).
3. «مرشح للإضافة تقديرياً: Z (بعد استبعاد الموجودين بالهدف — الفحص التقريبي)» مع تحذير الدقة.
4. يُغذّى داخلياً كتجميع مباشر (G-OPS scrape مصغّر) ثم يُنفَّذ كـ F2 من خطوة 5 بسلاسة واحدة (Progress مرحلتان معروضتان: «الجمع… ثم الإضافة…»).

## 5. S03-F5 — متعدد المصادر (ملفات+قروبات)
- تجميع مصادر: ملفات (G-FILE-PICK multi) و/أو قروبات (تُجمع فورياً بمنطق S02 داخل OPS) ⟶ «إجمالي المرشحة Z» + ☑️ إزالة المكرر عبر المصادر.
- ثم F2 من خطوة 2.

## 6. S03-F6 — استئناف عملية سابقة
- قائمة الجزئية☑️ (اسم الهدف|ملف|progress|آخر حفظ|الإعدادات). نقرة: تفاصيل نقطة التوقف (آخر عنصر، عدادات الحسابات تلك اللحظة).
- أزرار: «▶️ استئناف بنفس الإعدادات» (G-OPS من نقطة الحفظ) | «✏️ إعدادات معدّلة» (خطوات 4–6 بـF2 مع حفظ الـcheckpoint) | «🗑 حذف الحفظ» (خطير).
- Idempotency: العناصر `uncertain` تُفحص عضويتها في الهدف قبل إعادة تنفيذها (تتعلم من رفض `USER_ALREADY_PARTICIPANT`).

## 7. S03-F7 — القائمة السوداء ⟶ G-BLACKLIST(mode=users)
(تعريف S00 §12.11 — مخصصة إعداداتها هنا من أحداث F2 تلقائياً حسب G-PROTECTION).

## 8. S03-F8 — سجلات وإحصائيات الإضافة
- سجل العمليات (جدول كامل) + فلاتر تاريخ/نتيجة/هدف + نقرة عملية: تقريرها + أزرار «🔁 إعادة بنفس الإعدادات» «📂 قائمة الفاشلين» «G-EXPORT». (صورة مدمجة مع S07-F7 لكن مختصرة للنوع فقط.)
- إحصاءات عامة: معدلات النجاح/حسب السبب/أداء حسابات/أكثر أهدافك استهدافاً + رسم + تصدير. حالات فارغة.

## 9. S03-F9 — إعدادات افتراضية للإضافة
(تأخيرات/حدود/تبديل/سلوك أخطاء/حفظ تقدم/حد ذكي) بنفس حقول G-ACCOUNTS-STRATEGY + G-PROTECTION؛ حالة كل حقل (افتراضي/مخصص/غير محفوظ) + «🔄 إعادة للافتراضي» (مودال عادي). تورثها G-ACCOUNTS-STRATEGY عند الفتح (قابلة للتغيير لكل عملية فقط).
